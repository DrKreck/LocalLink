# Участие в разработке

Обсуждение ошибки или pull request должны включать:

- версию LocalLink и Windows, выбранный метод и сервис;
- шаги воспроизведения, ожидаемый и фактический результат;
- результат офлайн-тестов, а для интерфейса — снимок без личных данных;
- отдельно: что проверено в сети, а что только в коде.

Не прикладывайте переписку, токены, приватные ключи, настройки VPN, аппаратные идентификаторы или полный сетевой захват. Достаточно минимального обезличенного примера.

## Изменения кода

Используйте C# 5 / .NET Framework 4.8 x64 и существующие средства сборки. Не добавляйте зависимости без необходимости. Проверяйте входные данные и сохраняйте ограничения размеров, отмену операций и корректную остановку собственных процессов.

Для сборки из исходников нужны Windows x64 и .NET Framework 4.8. Из корня исходников:

```powershell
.\tools\Setup-Engine.ps1
.\Build.ps1 -OutputDirectory .\artifacts\review
.\diagnostics\Test-UI.ps1 -BuildDirectory .\artifacts\review
.\tools\Test-AppUpdates.ps1 -OutputDirectory .\artifacts\update-lifecycle
.\tools\Test-UpdateSigning.ps1 -OutputDirectory <новая-папка-вне-исходников>
```

`Setup-Engine.ps1` подготавливает файлы для сборки; обычным пользователям он не нужен. Уже подготовленный движок можно передать параметром `-EngineDirectory` команды `Build.ps1`. Добавляйте регрессионный тест к исправлению.

Сборка и офлайн-тесты не запускают драйвер и не меняют сетевые настройки. Живые сетевые проверки выполняются отдельно.

## Автоматическая настройка и интерфейс

Сохраняйте явное разделение `AutomaticSetup` и `ConnectOnOpen`. Подбор при подключении включён по умолчанию, подключение при открытии — отдельное согласие, выключенное в старых настройках. Импорт пресета не должен включать это согласие, менять напоминания об обновлениях или переносить сетевые привязки. Кнопка автозапуска Windows и разрешение UAC остаются отдельными действиями.

Повторно используйте компоненты только после проверки закреплённых SHA256. Автоматическая подготовка Telegram должна учитывать выбранный установленный клиент; ручная кнопка может подготовить модуль отдельно. Не устанавливайте Discord, Telegram и другие сторонние клиенты вместо настройки уже установленных приложений.

Кеш методов — короткоживущая подсказка, не разрешение на запуск и не доказательство работающего аккаунта. Привязывайте его к хешам сети/настроек и поколения компонентов/списка, сохраняйте пределы 128 записей/128 КиБ/7 дней и перепроверяйте результат. Не переключайте методы уже работающего фильтра в фоне. Проверка публичных узлов не заменяет проверку звонка, аккаунта или игрового подключения.

Telegram-модуль в режиме `--auto-setup` использует собственный loopback-прокси и официальный URI с подтверждением в Telegram. Отметка предложения не означает принятие. Не читать и не менять `tdata`, файлы сессии или пользовательские настройки прокси напрямую; не добавлять секрет или URI в журнал. Сохраняйте ручное повторение предложения и независимый жизненный цикл модуля.

Настройки состоят из пяти разделов; ручные сетевые параметры и технический журнал находятся в «Дополнительно». В `Test-UI.ps1` проверяются переходы, скрытые/отключённые контролы, отмена между этапами, импорт/восстановление и сочетания темы/размера окна. Геометрическая симуляция масштаба 100–200% не является проверкой настоящего per-monitor DPI; отмечайте их результаты отдельно. Синтетические формы не должны запускать реальные сетевые операции даже при включённой автоматической настройке.

## Подготовка выпуска

Соберите и проверьте версию, экспортируйте публичные исходники через `Export-OpenSource.ps1`, затем сформируйте Windows-архив через `Package-Release.ps1`. В выпуск входят Windows-архив, архив исходников и файлы подписи обновления. Публикация выполняется владельцем проекта; приватные файлы рабочей папки в экспорт не входят.

Production updater требует манифест с подписью RSA-4096, подходящей закреплённому `AppUpdateClient.TrustedManifestPublicKeyXml`; неподписанный fallback не допускается. Приватный ключ не добавляется в исходники, fixtures общего доступа или архивы. Настройка и подписание описаны в [UPDATE-SIGNING.md](docs/UPDATE-SIGNING.md). При локальной пересборке с другим публичным ключом это другой канал доверия, не подпись официального владельца.

Сохраняйте отдельность настроек напоминаний от сетевых пресетов: «Позже» и «Не напоминать об этой версии» не означают согласие на установку; выключение автоматики не отключает ручную кнопку. Ни обновление, ни откат не должны продолжаться после ошибки обязательного сохранения настроек.

Помощник установки должен работать неповышенным. Повышенный GUI использует доверенный Explorer и проверяет ответ готовности до остановки приложения; при невозможности перехода — отказ без ослабления защиты. Модельные проверки и проверка обычного процесса не подтверждают живой переход high-to-medium: фиксируйте такой результат отдельно, когда он реально выполнен.

## Подготовка runtime разработчиком

Обычные пользователи устанавливают компоненты из приложения. Для пересборки runtime используется `tools/Build-TelegramRuntime.ps1 -SourceDirectory <подготовленный CPython> -OutputDirectory <новая папка>`. Закреплённые версии: CPython 3.12.14, cryptography 50.0.1, cffi 2.1.1, pycparser 3.0. Готовую папку можно передать `Build.ps1 -TelegramRuntimeDirectory <папка>`; существующий runtime не перезаписывается. Закреплённые файлы и лицензии сохраняются.

Сохраняйте лицензии и атрибуцию сторонних компонентов. Вклад в авторский код проекта принимается на условиях MIT.
