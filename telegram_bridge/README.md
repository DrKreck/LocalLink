# Telegram

Отдельный локальный мост для Telegram Desktop. Звонки не поддерживаются.

1. Запустите `LocalLink.Telegram.exe`.
2. Дождитесь «Готов» и нажмите «Подключить Telegram».
3. Подтвердите прокси в Telegram.

Окно закрывается в трей. Для выхода используйте «Остановить». Перед выходом отключите этот прокси в Telegram, иначе клиент продолжит подключаться к остановленному модулю.

## Runtime

Модулю нужен изолированный Python runtime в `telegram/runtime`. Готовый runtime передаётся сборке через `Build.ps1 -TelegramRuntimeDirectory <папка>`; его файлы проверяются по `runtime-manifest.json`. Он не входит в публичный пакет исходников или пакет программы без зависимостей.

Для подготовки runtime из своей установки CPython используется `tools/Build-TelegramRuntime.ps1 -SourceDirectory <папка Python> -OutputDirectory <новая папка>`. Текущий упаковщик принимает CPython 3.12.14, cryptography 50.0.1, cffi 2.1.1 и pycparser 3.0; остальные версии нужно проверять отдельно. Упаковщик не устанавливает Python или пакеты автоматически. Лицензии Python и зависимостей сохраняются в runtime.

Для публичного Windows-архива откройте PowerShell в корневой папке LocalLink и выполните:

```powershell
.\tools\Build-TelegramRuntime.ps1 -SourceDirectory "<папка подготовленного CPython>" -OutputDirectory ".\telegram\runtime"
```

Папка `telegram/runtime` должна ещё не существовать: упаковщик отказывается перезаписывать готовый каталог. После успешной подготовки можно открыть модуль кнопкой в настройках LocalLink или запустить `telegram\LocalLink.Telegram.exe`; пересобирать готовую программу не нужно.

При сборке из исходников подготовьте runtime в отдельной новой папке и передайте её через параметр `-TelegramRuntimeDirectory`. Скрипт и файл `telegram_bridge/python312._pth` уже включены в публичные исходники и Windows-архив; сами бинарники Python пользователь подготавливает отдельно.

## Работа

Модуль слушает `127.0.0.1:1443`. Локальный секрет прокси защищён DPAPI текущего пользователя и хранится в `proxy-secret.dpapi`. Это не ключ аккаунта Telegram; не публикуйте этот файл.

Мост преобразует внешнюю обфускацию MTProxy в MTProto через TLS/WebSocket к узлам Telegram. Проверка сертификатов включена; внутреннее шифрование MTProto не снимается. Данные аккаунта и переписка не читаются. Исходящие соединения привязываются к одному физическому IPv4-адаптеру, а при изменении сети модуль пытается восстановить собственные соединения.

DNS, маршруты, системный прокси и брандмауэр не меняются. Модуль работает отдельно от главного окна LocalLink. Наличие WSS-соединения ещё не означает, что сообщения и медиа доступны: это проверяется в самом Telegram.

Ограничения: до 8 соединений, кадры до 1 MiB, экспериментальные направления DC2/DC4. Доступность зависит от сети и узлов Telegram.
